# 页面交互与角色操作

页面采用 Arco Design 浅色视觉规范：白色导航、亮蓝主色、浅灰底色和小圆角控件。登录默认进入当前角色的工作台，常用业务在侧栏直接展示，其余查询保留在“更多业务”的分组中。列表用于查找记录，详情用于查看关联资料和处理阶段，办理动作按角色与状态呈现，服务端在提交时重新校验。

老人档案、评估和照护计划供本社区管理员、已关联家属和承担照护的护工查阅。街道审核和民政终审从补贴申报查看订单与核算依据。民政人员另可查看授权辖区内的应急事件和待处置队列。

桌面端的服务订单列表把项目和订单号放在一起，预约时段同时显示开始与结束时间。点“详情”可核对地址、金额、护工的签到签退时间、服务记录和家属确认。若发生改派，展开“此前的派单”可查当时的护工及原因。街道审核人员可从申报核验单的“服务详情”进入同一笔订单。

## 六种角色的首页

| 角色 | 首页内容 | 办理方式 |
| --- | --- | --- |
| 老人及家属 | 老人切换、照护概况、下一次服务、待确认、最近服务、费用与补贴、生活照片 | 预约预选当前老人；确认先查看服务详情；费用和反馈按当前老人进入列表 |
| 护工 | 指定日期的服务日程、待接单、本月工时、此前未完成任务、自己的班次与证书 | 在任务行接单、签到或签退；异常上报带入健康或居家环境的说明前缀 |
| 社区管理员 | 应急提示、待派单、复评、投诉、可申报订单 | 从具体记录进入派单、评估、投诉受理与申报准备 |
| 机构负责人 | 排班与容量、工时复核、证书、招聘培训、考核材料、超时订单及整改 | 查看本机构记录，按实际状态复核、提交材料或退回调度 |
| 街道审核 | 待初审列表、订单与金额依据、家属确认、归档材料和审核历史 | 先核验，随后打开原有审核表单填写意见；状态变化后不重复审核 |
| 民政监管 | 授权社区覆盖与及时响应统计、终审、拨付、整改复核、机构材料与应急 | 社区筛选约束统计、补贴和应急；机构材料及整改区域明确标注全部授权范围 |

家属页以老人资料卡为中心，依次呈现所属社区、责任护工、评估有效期和照护计划；下一次服务与费用分区显示。护工页以日期和任务日程为主，支持“回到今天”，证书缩略图可进入对应证书记录。机构页在左栏安排排班、招聘与培训，右栏集中异常工时、整改和考核材料；班次数量随日期查询变化。

街道页采用待审队列与申报核验单双栏布局，核验单按服务依据、材料历史、审核处理三个部分组织。民政页用社区数量、服务覆盖率和及时响应率呈现统计概况，环形图与显示数值使用同一查询结果，右侧集中终审和拨付入口。窄屏下各区块按阅读顺序排列。

家属费用使用当前老人的累计已完成订单，补贴仅扣除这些订单对应的已拨付金额。监管统计使用本月全部授权社区，展示分子和分母，分母为零显示“—”。页面不将当前分页数据加总为全量统计，也不将未审核补贴表示为到账金额。

日程在数据库按服务时间与编号排序后分页；班次按与所选日期相交的时间区间查询，包含跨午夜班次。表格中的完整历史记录可从“查看全部”进入。老人切换重新查询其授权数据，当前标签页的返回和刷新保留老人选择，退出登录清除当前导航状态。

首页每 30 秒刷新待办，同一查询刷新时保留正在阅读的内容；切换账号、老人或筛选条件时不复用其他范围的数据。加载失败显示错误与重试，不以零代替失败。未提交表单由现有抽屉保留，不因后台刷新重新打开或提交。

## 列表和表单

| 角色 | 常用待办 | 记录上的操作 |
| --- | --- | --- |
| 社区管理员 | 待派单、待受理投诉、待处理应急、评估到期 | 从老人档案预约和登记评估；订单派单；投诉受理、社区回复及结案；补贴补件重报 |
| 老人及家属 | 待确认服务、预约记录、投诉进度、补贴进度 | 为关联老人预约、求助；确认服务、评价和投诉；取消尚未开始的预约 |
| 护工 | 待接单、待上门、服务中、应急待响应 | 对本人当前任务接单、签到签退、退回调度；按应急阶段核实、响应和登记处置 |
| 机构负责人 | 工时待复核、待回复投诉、待整改、待审应聘 | 排班、证书及在岗状态维护；工时复核；投诉回复、整改提交、招聘培训办理 |
| 街道审核 | 待初审、已初审、辖区服务、通知 | 对已提交的补贴进行初审；查看核算依据、材料和审核记录 |
| 民政监管 | 待终审、待拨付、整改待复核、机构材料待审 | 补贴终审和拨付；整改及机构材料审核；查看辖区统计 |

标题下按业务和角色显示简短操作说明；字段要求、操作后果和错误提示保留在相应位置；工作台“关于平台”说明数据与图片来源。业务列表使用整栏宽度，角色待办显示为紧凑按钮，快捷办理集中在表格上方；家属首页保留社区生活照片，通过底部圆点切换。手机端导航可展开，选择页面后自动收起，记录以卡片显示。页面使用 React、TypeScript 和 Arco Design React。表格、菜单、抽屉、弹窗、日期选择与表单控件来自组件库，页面布局在 `frontend/src/styles` 中维护。桌面使用表格，手机使用记录卡片；业务提示、必填标记、禁用状态和错误反馈随字段展示。


页面采用蓝色主题，标题配业务图标；工作台首项指标突出显示，其他指标与内容使用白色卡片。排班和培训在宽屏采用双列卡片，窄屏采用单列；筛选区与记录区之间保留明确分隔。

护工排班按班次展示日期、时段、护工、开放状态和名额占用；课程与培训成绩突出课程名称、参训人员、结果和分数。通知消息与质量公示采用正文列表，保留详情入口；应急通知可进入关联事件。费用、补贴进度、服务区域与工时汇总列表展示主要业务字段，完整记录保留在详情中。

职业证书以图片卡片展示持证人、类型、等级、证书编号和有效期，支持放大预览、下载 SVG 图片及查看登记详情。图片由登记字段生成，标注为平台资料预览，不代表发证机构原件。

服务工时在筛选区下显示总有效工时、有效记录数、待核验记录数和无效记录数。汇总采用当前账号授权范围及相同筛选条件，通过分页读取全部匹配记录计算，不随列表翻页变化。仅 `VALID` 记录的 `effective_minutes` 计入总时长；`PENDING` 与 `REVIEW` 归入待核验。时间以小时和分钟展示，空结果为零，加载失败显示重试。证书和工时页使用各自的业务内容，不展示通用待办条。

## 查找与关联

关键词、状态和日期筛选在服务端执行，然后计算总数并分页；不局限于当前页。刷新保留筛选，清除筛选恢复全部授权记录。日期条件按界面标明的业务时间字段解释，结束日期包含当天。状态选项只取自当前账号可查询的数据。

老人详情可以进入该老人的订单、计划和评估。护工详情可以进入对应班次和证书。表单以姓名、服务名称和时间显示候选项，保留编号用于区分同名记录；支持输入关键词查找和继续加载。

预约表单按“老人 → 预约时间 → 服务项目 → 下单渠道”单列排列，显示顺序与键盘填写顺序一致。选定老人和时间后，根据有效照护计划提供计划内项目；前置条件不全、正在加载或没有可预约项目时，项目选择保持禁用。切换老人或时间会清空旧项目，加载失败可以重试。照护计划中的评估须先选择老人，派单中的班次须先选择订单。

派单时调用现有推荐业务列出符合资格、区域、时段和容量条件的护工班次，正式提交仍在事务中重新检查。补贴订单、政策适用社区和服务包项目使用勾选或逐项添加。

| 表单 | 填写方式 |
| --- | --- |
| 家属联系方式 | 先选老人，再选家属关系，带出现有关系、电话和有效状态。更换老人时清空原家属信息。 |
| 照护计划 | 原计划和评估限定为所选老人；服务包按评估能力等级筛选，单独配置的项目限于所选服务包。 |
| 招聘审核 | 录用时填写账号和初始密码；不录用时隐藏这两项，也不提交其内容。 |
| 抽查结果 | 先决定是否整改，再填写整改要求；评分低于 60 分时必须整改。 |
| 补贴申报 | 政策决定月、季、年周期格式；订单按老人、项目、周期、政策有效期和可申报记录筛选，可全选、清空。年龄、标签、评估及周期重叠等资格仍由提交时的业务校验确定。 |
| 服务包和适用社区 | 项目逐项添加，每周次数为正整数，重复项目不可选；社区可以搜索并批量勾选，搜索不丢失已有选择。 |
| 采样记录 | 可粘贴 JSON 或导入本地 JSON 文件，检查记录结构及条数后再提交；文件解析失败保留原输入。 |

时间区间、证书有效期、评分、次数和抽查比例在输入时校验。审核意见、服务记录、问题说明等使用多行输入。服务评分按 1 至 5 分选择，初始密码支持显示与隐藏。

## 提交与反馈

从记录发起操作时带入关联对象。成功后刷新记录与待办数量，显示操作结果和查看记录入口；本次表单不能重复提交。失败保留输入，显示服务端返回的原因。取消预约、删除班次、迁移及拨付等操作在提交前确认；关闭未提交的表单提示保留或放弃。

点击“更新老人住址”等具体操作后，表单直接显示该事项的字段。其他事项从相应业务页进入，低频操作收在“更多办理”里。社区管理员可在“评估到期提醒”页手动检查到期和超时事项。查找关联对象时清空依赖旧对象的选择，加载期间和加载失败时不允许提交失效的候选项。

详情中的阶段条表示当前业务状态，具体时间、经办人和意见来自下方实际记录。阶段条不生成不存在的历史记录。手机上的列表以记录卡片展示，优先显示两个常用动作，其余操作通过“更多操作”进入详情。详情按资料分组，桌面双列、手机单列；从记录进入表单时显示办理对象，更换对象后不保留原记录提示。无匹配结果时可直接清除筛选。

## 实现与验证

前端位于 `frontend`。`model/rules.ts` 定义角色及状态动作，`forms/schema.ts` 处理字段顺序、条件、输入校验和提交内容；`RecordSelect` 与 `LinkedFields` 处理关联选择；`OperationDrawer` 处理草稿、确认、重复提交和结果反馈。`Workspace` 组织导航、列表、筛选和手机卡片；`pages/workspaces` 按六个角色分别组织首页，复用加载状态、待办行及既有状态动作。密码由专用弹窗维护，登录状态统一管理。

查询接口 `/api/data/{kind}` 支持 `page`、`size`、`search`、`status`、`from`、`to`、`field`、`value`。后端 `ListFilter` 校验参数，`ListFiltering` 在授权 SQL 外增加参数化过滤。关联字段使用固定白名单，不接受任意 SQL 列名。Java 17、Spring JDBC、MySQL、DDD 风格分层和事务入口保持现有约定。

构建和浏览器运行说明见 [前端开发说明](../frontend/README.md)。`scripts/react/verify_pages.cjs` 走查七个账号的列表、详情、表单入口和多种屏宽；`verify_workflows.cjs` 检查履约、投诉、招聘培训、应急、整改公示和分级补贴；`verify_records.cjs` 检查建档、家属关系、计划及跨社区流转；`verify_passwords.cjs` 检查重置、强制改密和会话失效；`verify_forms.cjs` 检查依赖、重试、条件字段、导入及草稿；`verify_media.cjs` 检查头像、轮播和手机卡片；`verify_claims.cjs` 检查补贴订单勾选、申报材料、驳回重报和政策社区选择。

React 业务办理记录及截图保存在 `evidence/react`，自然名称与逐角色页面检查保存在 `evidence/natural-names`；Java/MySQL 结果在 `evidence/test-summary.json`。工作流和密码脚本会写入课程测试数据，需使用独立真实 MySQL 测试库。页面入口覆盖、浏览器业务提交和数据库回归分别记录，不能互相替代。

## 工作台查询与验证

`WorkspaceQueries` 提供账号资料、家属照护概况、日程、后续预约、未完成任务、班次、有效工时和应急投影；`GovernanceQueries.jurisdictionSummary` 对授权社区的完整集合汇总。所有 SQL 继续放在基础设施层，经 `ReadService` 和 Spring JDBC 执行。排序由服务端查询模块定义，不接受用户提供的 SQL。此次页面功能不增加业务表，也不需要数据库迁移。

`scripts/react/verify_workspaces.cjs` 检查六角色首页、真实数量和记录、预约预选、老人切换、刷新与返回、材料区保留、错误重试以及 1600、1280、768、390 像素布局。`WorkspaceIntegrationTest` 检查费用口径、完整授权集合汇总、角色与社区隔离、解绑失效、分页排序、跨午夜班次和账号资料。运行说明仍遵循独立 MySQL 测试库要求。

### 桌面办理

社区工作台把仍可派单和已错过预约时段的待派单分开。进入“已过预约时段 · 待联系”，核对老人及订单后联系家属，再选择“联系后改约”或“取消预约”。改约保留原订单、项目和时长，新时段须符合照护计划。超时调度池保留等待超过 15 分钟且时段尚未结束的订单。

家属从家人卡片预约时，依次核对老人、选择时间和服务项目。护工当天无服务、无班次且无遗留任务时，日程集中显示一条提示。民政工作台区分等待响应、未响应超时、已响应待到场和已到场待结案。

服务工时按当前账号和筛选条件由数据库汇总。总分钟数只累加有效工时，待核验包括待判定和待复核记录。翻页只切换明细。月工时按护工和月份区分。

护工接手应急事件后，即使该老人的照护任务结束，仍能跟进这一起事件、登记到场并结案。设备解绑后，家属和护工在体征记录中查看其有权查阅的历史采样；当前设备详情按有效绑定显示。
