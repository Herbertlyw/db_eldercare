## 二、优先处理的业务问题

1. **签到与退回调度可能对同一单做出互相矛盾的决定（代码确认，未做并发压测）。** `OrderService.releaseOrder`、`attendance` 先通过 `scope.order` 普通读取，再锁订单；锁查询只返回编号，状态判断仍用第一次读到的对象。护工签到后订单进入服务中，但此时派单记录仍是 ACCEPTED。一个刚拿到锁的退回请求若仍按旧订单状态判断，就可能退派、释放班次名额，并把已有签到的订单改回待派。相关位置：`OrderService.java:145`、`JdbcOrderRepository.java:125`。建议在锁内取得订单当前状态，状态更新带前置条件并核对影响行数。验收条件：同一单同时签到与退回，只允许一种一致的结果。
2. **整改复核可能出现“材料已通过，抽查又被退回”（代码确认，未做并发压测）。** `GovernanceService.java:61` 先读 REVIEW 后加锁。第二个复核人在锁外读到 REVIEW；等第一个人通过后，材料表已经没有 PENDING 行。第二次更新材料可以影响零行，但代码仍按编号写抽查主表。建议在锁内验证状态，并要求本次待审材料恰好更新一行。验收条件：两次相反决定竞争时只有一次成功，材料决定、主表状态、审计结果一致。
3. **民政首页把已按时响应的事件提示为超时（实测）。** 展示库事件 28 为 RESPONDED，响应时间不晚于初始截止。首页实际文字却是“已超过当前响应期限”。`RegulatorHome.tsx:215` 只判断剩余秒数；待办视图还包含已响应、尚未结案的事件。应先按事件状态分支：未响应才显示响应倒计时，已响应显示待到场或待结案。及时响应率的 SQL 比较的是响应时间和初始截止，不应为修文案去改这个指标。
4. **错过整个服务时段的订单和当前可调度订单混在一起（数据与代码实测，处置方式需定）。** 11 月 18 日检查时，青禾社区的 16 笔待派单中有 8 笔预约结束时间已过。列表仍展示派单动作；推荐 SQL 和派单过程检查班次是否覆盖原预约，但没有单独要求该时段尚未结束。超时未接单与预约时段已过去是两种业务事实。建议保留前者的调度池，为后者提供联系改约或取消入口；是否允许事后补登要单独定义，不应直接当作今天能派的服务。任务书未规定自动取消期限。

## 三、代码质量：值得动哪里

- **工时总数用数据库聚合。** `HoursSummary.tsx:24`、`api/client.ts:59` 按每页 100 行把所有匹配明细取回浏览器才汇总。它能跨页计算，不能说当前漏算；但只看几个数字也要传输全部明细。可共用同一授权与筛选条件，在 SQL 中用 SUM、COUNT 分组返回。原有跨页和异常工时测试可直接作为对照。
- **减少工作台的重复查询。** 本轮实测机构负责人首次打开首页触发 13 次 `/api/data/` 请求，管理员 12 次。部分指标为了读总数也会通过通用分页管道查列、状态、总数和一行明细。首页按 30 秒刷新。先合并同口径的计数与列表，看实际请求数和响应时间再决定是否缓存；当前没有证据称页面已经卡顿。
- **按业务定义行标识。** 月工时 SQL 按“护工＋月份”分组，返回的 `id` 却只是护工号；桌面表格和手机卡片用 `id` 作 React key（`WorkforceQueries.java:126`、`Workspace.tsx:791`、`Workspace.tsx:859`）。同一人跨月会出现重复键，默认仅按首列排序也无法确定月份顺序。展示库本轮未出现同一人跨两月的有效工时，属于跨月边界问题。用护工与月份组成稳定键，并显式按月份和护工排序。
- **拆改动热点，无需重做分层。** `Workspace.tsx` 有 921 行，涉及路由、筛选、轮询、导航和记录渲染；通用 `Row`、`Values` 为 `Record<string, any>`。优先为工时、事件、申报这类有明确状态和统计口径的投影给出类型，把记录列表与导航独立出来。现有 JDBC 边界可保留；补贴审核的“先锁再判”也可作为其他流程的参考。

## 11 月 18 日桌面验收

签到和退回调度竞争同一笔订单时，后到的事务取得锁后读取当前状态。双连接验证中，签到成功，退回请求被拒绝，订单保持服务中，签到记录和班次名额一致。两位监管人员对同一份材料作相反决定时，第二次复核被拒绝，主表、材料、复核人和复核意见一致。

本机展示库的 28 号事件显示“已响应，待到场”。青禾社区本次检查时有 9 笔待派订单错过整个预约时段，单独列为待联系。家属提交预约、管理员联系后改约的写操作在独立副本执行。本机展示库只升级了派单过程，核对了 47 张基础表升级前后的行数。

独立 MySQL 库上的 Maven 测试共 199 项，前端单元测试共 30 项，全部通过。工时回归用 106 条记录核对角色范围、各状态数量及跨页有效分钟数。桌面浏览器覆盖家属预约、社区调度、护工日程和工时、机构工时、街道申报入口及民政应急提示。具体办理入口见[页面交互与角色操作](页面交互与角色操作.md)。
