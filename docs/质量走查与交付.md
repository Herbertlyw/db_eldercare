## 环境与复核

- **基线与最终组合**　基线 Java 199 项、前端 32 项。第一批 Java 202 项、前端 36 项。平台构建提交为 `4dc6d6c`，在该提交的干净源码副本中重新打包并运行完整 Java 测试，183 项 MySQL 集成、38 项独立测试均通过，零失败、错误或跳过。第一次组合运行失败 1 项，原因是新增用例留下了家属关系。让用例在结束时回滚后，原断言通过。
- **桌面实办**　固定业务数据关闭调度器。使用六类角色、七个账号逐页走查。不同账号进入同一业务各计一次，共 144 个页面入口、140 次详情检查和 87 个表单入口。街道补贴和民政应急详情另在 Chrome 125% 缩放下核对字段、布局、Tab 和 Esc。还检验了写入后的另一角色可见性、搜索、翻页、空结果、错误重试、失效选择清除、旧会话、确认后果及图片回退。写入结果另按业务链验证。React 类型、36 项单测、Prettier 和 Java 格式检查通过。 [改选订单后的取消确认](../evidence/quality-20261121/order-confirm.png) · [街道核验补贴详情](../evidence/quality-20261121/street-claim.png)

- **实际调度**　后台服务在专用库独立运行约 62 秒，观察两个周期。到期计划和被新评估替代的计划暂停，评估提醒去重，应急各升到二、三级，设备新增两条模拟采样。固定数据页面使用的服务始终关闭后台任务。
- **迁移与恢复**　已有库副本升级前、升级后和再次执行后的 47 表数据摘要相同。升级后 17 个视图、74 个触发器、12 个存储过程，新建库与升级后库的过程定义一致。另在独立源库做全量备份并回放真实 binlog 增量，47 张表内容逐表核对，恢复后执行 15 组双写法查询比对，新增标记可查回。在有活动连接的测试库实际尝试重建，脚本在删除数据库前退出。恢复脚本的最终验证版本为 `63a08f3`。
- **架构与数据库账号**　四条架构测试核对领域层依赖、应用服务与模块边界。针对测试库核对应用账号的直接授权，业务读写使用 SELECT、INSERT、UPDATE、DELETE 和 EXECUTE。实例管理、建库及备份使用本机维护工具。
- **连接与运行方式**　MySQL 8.4.11、Asia/Shanghai、原生 JDBC。桌面检查前将指定端口的 Java 进程与 MySQL 实际连接配对。完整库名、端口、检查命令及摘要见[验证记录](../evidence/quality-20261121.json)。工作目录 `eldercare-quality` 单独集成，以普通快进推送更新远端 main。本地 main 被另一工作目录使用。

## 还需决定或另行执行

- 任务书 2.1.1 要求记录服务频次。超出每周计划后提醒、拒单或计费的处理方式，需要另定。家属通常关联几位老人、家庭跨社区时由谁核验关联，也保留为产品决策。展示库中的亲属关系按逐角色走查结束后的决定再处理。
- “预约已先占用计划，另一事务仍能暂停计划”在强制交错的实验中未复现。原实现等待下单事务并拒绝暂停，保留测试用例。
- 已有数据库升级前先备份，在副本演练。正式升级时暂停定时任务和手动巡检，执行[社区维护存储过程迁移](../database/migrations/20261121_community_maintenance.sql)，核对四个相关过程后运行配套程序。失败恢复和旧程序回退见[迁移说明](../database/migrations/README.md)。本次实际写入限于独立测试库及恢复目标。
- 课程报告和 PPT 中按旧快照列出的 10 个过程，与当前 12 个过程有差别。Windows 实机、外部部署、长期备份排程及生产负载均未验收。
